# Booking API — демо REST API сервиса бронирования (pet-project)

Самостоятельный демонстрационный проект для портфолио, не привязан к
реальному заказу или клиенту. Показывает типовой стек и подход, которые
продаются в кворках «REST API» и «Docker-деплой»: FastAPI + SQLAlchemy +
PostgreSQL, JWT-авторизация, защита от гонки при бронировании, Docker,
CI/CD через GitHub Actions.

Важно честно: этот код написан и синтаксически проверен (`python -m
py_compile`), но не запускался в реальном окружении — в песочнице, где он
готовился, нет доступа к PyPI и Docker-демону, чтобы поставить
зависимости и поднять контейнеры. Логика проверена по коду и по best
practices FastAPI/SQLAlchemy, но перед тем как показывать проект
заказчикам, его нужно реально запустить у себя и снять настоящие
скриншоты — см. шаги ниже. Не выдавайте скриншоты чужих проектов или
непроверенный код за рабочий результат.

## Что показывает проект

- **Модель предметной области**: услуги → слоты (конкретное время) → брони,
  с уникальным ограничением на пару (услуга, время слота) и на слот в брони.
- **JWT-авторизация**: регистрация, логин, `Depends` для текущего
  пользователя и отдельно для администратора.
- **Защита от двойного бронирования**: `SELECT ... FOR UPDATE` внутри
  транзакции при бронировании слота + `UNIQUE(slot_id)` как вторая линия
  защиты на случай гонки (`app/routers/bookings.py`).
- **Docker + docker-compose**: приложение и PostgreSQL поднимаются одной
  командой.
- **CI/CD**: GitHub Actions — устанавливает зависимости, поднимает
  тестовый PostgreSQL, проверяет, что приложение импортируется и роуты
  регистрируются, собирает Docker-образ; на ветке `main` — шаг деплоя.

## Структура

```
app/
  main.py         — точка входа FastAPI
  config.py       — настройки из .env
  database.py     — подключение к БД
  models.py       — SQLAlchemy-модели
  schemas.py      — Pydantic-схемы
  security.py     — хеширование паролей, JWT
  deps.py         — зависимости (текущий пользователь/админ)
  routers/
    auth.py       — /auth/register, /auth/login
    services.py   — /services, генерация слотов
    bookings.py   — /slots, /bookings
Dockerfile
docker-compose.yml
.github/workflows/ci-cd.yml
```

## Как запустить и снять скриншоты для портфолио

1. `cp .env.example .env`, вставить свой `JWT_SECRET_KEY` (`openssl rand -hex 32`).
2. `docker compose up --build` — поднимет API на `http://localhost:8000` и PostgreSQL.
3. Открыть `http://localhost:8000/docs` — автосгенерированный Swagger UI.
   **Скриншот Swagger UI со списком эндпоинтов — в портфолио.**
4. Через Swagger или Postman: `POST /auth/register` → `POST /auth/login`
   (получить токен) → `POST /services` (нужны права админа, см. ниже) →
   `POST /services/{id}/generate-slots` → `GET /slots` → `POST /bookings`.
   **Скриншот запроса и ответа в Postman/Swagger — в портфолио.**
5. Чтобы сделать пользователя администратором для теста —
   `UPDATE users SET is_admin = true WHERE email = '...';` напрямую в БД
   (в реальном проекте это делался бы отдельным защищённым механизмом).
6. Открыть структуру проекта в IDE и сделать **скриншот дерева файлов**
   для портфолио — показывает архитектуру, а не один файл.
7. Для CI/CD: залить проект в свой репозиторий на GitHub, workflow
   `.github/workflows/ci-cd.yml` запустится автоматически на push —
   **скриншот зелёного прогона в GitHub Actions** для портфолио.
8. Для демо HTTPS-деплоя (кворк про Docker-деплой): поднять на своём
   VPS/хостинге через `docker compose up -d`, настроить обратный прокси
   (например, Caddy или nginx + certbot) для HTTPS — **скриншот
   открытого `/docs` по https:// с валидным замочком** для портфолио.

## Технологии

Python, FastAPI, SQLAlchemy 2.0, PostgreSQL, Pydantic v2, JWT
(python-jose), passlib/bcrypt, Docker, docker-compose, GitHub Actions.
